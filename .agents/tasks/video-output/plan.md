## Scope guard (restated)

In scope: the two VideoView surfaces, the `VideoLAN.LibVLC.Windows` package ref, one-time `Core.Initialize()`, lifecycle disposal safety, the pure `VideoRouteResolver` + its tests, and the single `OnItemChanged` routing hook. Out of scope: songs/templates/scripture/service-groups/bulk-edit internals, NDI, stage display, and any audio-engine changes.

## Note on assumptions

- A full-screen service `Video` item plays once (`Loop=false`); looping is reserved for motion backgrounds via the theme path. If the product wants looping welcome/countdown videos, that is a trivial follow-up (add a `Loop` flag to the item and honor it in `ShowVideo`), but it is NOT assumed here to keep scope minimal.
- Video file path for a `Video` service item is read from `ServiceItem.MediaPath`; if a future UI stores it elsewhere, update `VideoRouteResolver.Resolve` only (single, tested choke point).
